# 10. Веб-интерфейс (web/)

> Обновлено: 2026-07-24.

## Что это

`web/` — React-дашборд для Tuck, форкнутый из UI-shell [Remnawave](https://github.com/remnawave/frontend) (тема, layout, sidebar, базовые компоненты). Вся бизнес-логика страниц написана с нуля под API Tuck — 20 разделов: KV v1/v2, Tokens, Policies, 5 методов аутентификации, 4 бэкенда динамических секретов, 4 крипто-движка, wrapping, namespaces, token roles, audit sinks, cluster, mounts, plugins, replication.

Стек: React 19 + Vite + Mantine 9.4.1 + TypeScript + React Query + React Router v7 + i18next (EN/RU).

`web/` лицензирован отдельно как **AGPL-3.0-only** (см. `web/NOTICE`, `web/LICENSE-AGPL-3.0`) — из-за происхождения от Remnawave. Остальной репозиторий остаётся Apache-2.0.

## Локализация (EN/RU)

Полный перевод всех 20 страниц, форм, уведомлений и модалок через i18next. Переключатель языка — в шапке (иконка глобуса), хранится в `localStorage`, определяется автоматически при первом визите. Файлы переводов: `web/public/locales/{en,ru}/translation.json`, ключи сгруппированы по namespace (`common`, `kv`, `kv2`, `tokens`, `policies`, `authMethods`, `dynamicSecrets`, `cryptoEngines`, `wrapping`, `namespaces`, `tokenRoles`, `auditSinks`, `cluster`, `mounts`, `plugins`, `replication`, `login`, `status`, `header`, `nav`, `pages`) с переиспользованием общих строк (например `tokens.policiesLabel` используется во всех формах ролей).

## Редизайн интерфейса (2026-07-24)

Проведена доработка UX по референсу панели на базе Remnawave («BRUTALITY»): единый паттерн создания сущностей через модальные окна, карточки статистики над таблицами, донат-чарты для распределения по типам.

### Новые общие компоненты

- **`shared/ui/entity-modal/entity-modal.tsx`** — обёртка над `Modal` из Mantine с заголовком «иконка-чип + название» (как в референсе). Используется для всех форм создания/редактирования сущностей.
- Карточки статистики собираются из уже существующего `shared/ui/metrics/metric-card/metric-card.tsx` внутри `SimpleGrid` — отдельного компонента не потребовалось.

### Страницы, переведённые с инлайн-форм на модалки + добавлены карточки статистики

| Страница | Карточка(и) статистики | Модалка |
|---|---|---|
| Tokens | Всего токенов | Создание токена |
| Namespaces | Всего namespace'ов | Создание namespace |
| Token Roles | Всего ролей | Создание роли |
| Mounts | Всего + донат-чарт по типу движка | Регистрация точки монтирования + тюнинг (TTL) |
| Plugins | Всего + донат-чарт по типу (secret/auth/database) | Регистрация плагина |
| Audit Sinks | Всего + количество с ошибками | Создание приёмника аудита |
| Policies | Всего политик | Редактор политики (шаблоны + правила) |
| KV v1 / KV v2 | — (таблица уже была основной) | Запись секрета вынесена в модалку |

Все модалки открываются кнопкой «+ Новый» в шапке страницы (`PageHeader action`), список сущностей по-прежнему отображается таблицей по умолчанию — как и просил референс.

### Графики

Добавлена зависимость `@mantine/charts` (обёртка над `recharts`, тот же экосистемный стиль, что у остального Mantine UI):

- **Mounts** и **Plugins** — донат-чарт распределения точек монтирования / плагинов по типу (`secret`/`auth`/`database` и т.д.), с легендой сбоку. Данные реальные, считаются на клиенте из уже загруженного списка (`useMemo`), фейковых чисел нет.
- **Status** — `RingProgress` для прогресса unseal-шардов (`received_shards / required_shards`) вместо простого текста «X / Y».
- **Status → Активность**: карточки «Активные lease» и «Активные токены» теперь показывают реальные числа (`listLeases`, `listTokens`), вместо заглушки «Скоро». «Последние события аудита» и «Отставание репликации» **остались заглушками** — у бэкенда пока нет эндпоинта потокового лога аудита и метрики репликационного лага (см. «Дальнейшие шаги» ниже).

### Подсказки (hints)

Под заголовком модалок создания добавлена короткая серая подсказка (`Text c="dimmed" size="xs"`), объясняющая назначение сущности — по образцу референса (например у Kubernetes-роли уже была подобная подсказка, теперь она есть и у Tokens/Namespaces/Mounts/Plugins/Policies/Audit Sinks).

### Шрифт и цветовая палитра

Тема (`shared/constants/theme/theme.ts`, `colors-resolver.tsx`) была скопирована из Remnawave ещё на этапе форка M1 без изменений — тёмная схема с primary `cyan`, `Montserrat` для текста, `Fira Mono` для моноширинного. Жирный/капслочный логотип в шапке (`fw={800}`, `tt="uppercase"`) уже соответствовал референсу — дополнительных правок не потребовалось.

## Дальнейшие шаги (не сделано в этой сессии)

1. **Реальные графики трафика во времени.** У Tuck нет time-series эндпоинта (только текущий снэпшот `/v1/sys/health` и `/v1/sys/seal-status`). Чтобы построить график трафика/запросов как в оригинальном Remnawave, нужен либо бэкенд-эндпоинт с историей метрик, либо клиентский rolling-buffer поверх периодического опроса — сознательно не стали фабриковать фейковые данные.
2. **«Последние события аудита» на Status.** Нужен эндпоинт чтения последних записей аудит-лога (сейчас есть только управление приёмниками аудита, не сам лог).
3. **«Отставание репликации».** `getReplicationStatus` отдаёт `mode`/`state`/`last_sequence`, но не лаг в секундах/записях — нужно либо считать на бэкенде, либо сравнивать `last_sequence` primary/secondary на фронте (secondary-only метрика).
4. **Модалки для оставшихся форм.** Auth Methods (5 табов), Dynamic Secrets (5 табов), Crypto Engines (4 таба) пока используют инлайн-карточки для форм ролей/конфигов — по той же причине, что и остальные (там уже открывается/закрывается форма по кнопке, просто не в модальном окне). Перевод на `EntityModal` — механическая работа по уже отработанному паттерну, отложена по нехватке времени в рамках сессии.

## Локальная проверка

```bash
cd web && npm ci && npm run typecheck && npm run build
```

Собранные файлы попадают в `internal/ui/assets/` (гитигнорены, кроме `.gitkeep`) — обычный `go build ./...` их встраивает через `//go:embed`. Для разработки с hot-reload: `npm run dev` (проксирует `/v1`, `/v2`, `/openapi.json` на `localhost:8200`).
