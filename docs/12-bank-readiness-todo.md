## 1. Вопросы к ИБ банка — до начала пилота (P0)

- ⬜ Требуется ли **сертифицированное ФСБ СКЗИ** для данных, которые будут храниться (КИИ, ГИС, банковская тайна, ПДн)? Какого класса (КС1/КС2/КС3)?
- ⬜ Допустим ли несертифицированный ГОСТ как дополнительный слой, или нужен только сертифицированный (КриптоПро и т. п.) — тогда подключаем через `barrier.RegisterSuite`.
- ⬜ Где должен лежать корневой ключ: Shamir, HSM/PKCS#11, внешний KMS?
- ⬜ Требования к аудиту: куда, в каком формате, срок хранения, SIEM.
- ⬜ Допустимый уровень зрелости: нужна ли независимая оценка безопасности (пентест/сертификация) до пилота.

## 6. План пилота

1. Один сегмент банка, один Tuck на сегмент (не общий на все кластеры).
2. Только KV v2 + Kubernetes auth + оператор TuckSecret (`--enforce-namespace-paths`); экспериментальные движки выключены.
3. Миграция: секреты из Git (ansible-vault) → Tuck разовой загрузкой, затем `TuckSecret` вместо подстановки в Helm values.
4. Шифр барьера — по решению ИБ (§1): `aes-256-gcm`, несертифицированный `gost-kuznyechik-mgm`, либо сертифицированный СКЗИ через `RegisterSuite`.
5. Критерии выхода: независимый аудит (M1), отработанный аварийный сценарий (unseal, восстановление из бэкапа), согласованный SLA.
