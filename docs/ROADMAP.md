> **Состояние: v1.0.0 GA выпущен 2026-06-12.** Этапы M0–M32 и аудит безопасности завершены. Текущий цикл: v1.x.

---

## 1. Назначение системы

Tuck — встроенная система управления секретами для Kubernetes. Единый статический исполняемый файл (~20 МБ), без Consul, без etcd, без внешних зависимостей. Развёртывание выполняется командой `kubectl apply`.

**Целевая аудитория:** инженеры платформы, команды DevOps/SRE, которым необходима замена HashiCorp Vault без операционной сложности.

## 4. Архитектурные принципы

1. **Единый исполняемый файл** — отсутствие внешних зависимостей в среде выполнения
2. **Все данные через барьер** — открытый текст никогда не касается физического хранилища
3. **Минимальный интерфейс barrier** — каждый движок видит только Get/Put/Delete/List
4. **Паттерн 11 эндпоинтов** — все движки динамических секретов: CRUD конфигурации + CRUD ролей + учётные данные + CRUD аренды
5. **Фоновый GC каждые 15 минут** — истёкшие токены/аренды/обёрточные токены
6. **Приоритет запрещающих правил** — запрет в любой политике блокирует запрос независимо от разрешений
